# 專案知識與工作摘要

先找專案既有規則、決策與索引，核對實際程式／命令後復用。索引過期時直接查證；只在本次要求包含維護時更新，不把修索引變成所有工作的前置門禁。

區分三種產物，依需求只做所需部分：
- 本次交接：結果、決策理由、受影響檔案、驗證、未完成項及風險，引用既有 change 正文。
- 穩定知識：跨任務可復用的約定、接口、命令與回滾經驗，附日期、來源及驗證方式；在既有位置更新，不預設新增 memory/ 雙檔或固定條數。
- 日報／問答摘要：只依可見對話和實際紀錄；採使用者偏好的「編號標題＋子條列日志」，列已做動作與結果。缺少其他對話時說明覆蓋範圍，不編造全天紀錄，也不追加制式承諾句。

不複製整份 proposal/design/tasks 到記憶庫，不存憑證真值。新結論取代舊結論時保留來源及失效狀態，避免兩份 active 規則。正式封存契約由 devflow-marshal 按專案要求核對。

## Contract
- inputs_required: source_records、requested_scope。
- outputs_required: summary_or_stable_facts、source_links、unknowns。
- evidence_files: 使用者要求寫入時提供實際更新位置；純摘要無硬性檔案。
