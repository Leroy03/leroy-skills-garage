# 計畫檔

只在任務會跨對話、要交給其他 agent，或使用者要求時才寫。其餘情況用 Plan 模式或直接在對話裡給計畫。

一個任務一份檔，放在專案慣用的位置；沒有慣例時放專案根目錄，檔名 `PLAN-<主題>.md`。寫給沒有任何對話背景的人：只靠這份檔就能接手。

依序包含：
1. 目的與範圍：做完後可以觀察到什麼；明確列出不做的事。
2. 開始前確認：必須成立的前提；不成立時停下回報。
3. 步驟：依執行順序，每步寫要改什麼和怎麼驗證。有破壞性的步驟寫明備份或還原方式。
4. 驗收：實際要跑的命令或操作，以及預期結果。
5. 停止條件：遇到清單外的情況、驗證失敗或需要擴大範圍時停下回報，不自行改寫計畫。
6. 進度：勾選清單，每完成一步就更新；中斷時寫下停在哪裡。
7. 決策紀錄：執行中改變做法時，記一行原因。

保持精簡：只寫執行者無法從程式或文件查到的內容，不複述背景，不為完整而加章節。全部完成且驗收通過後刪除計畫檔，除非使用者要保留。
